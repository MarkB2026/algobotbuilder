4. Two distribution types

TYPE A

Standard installer

Mini-RSI and other prebuilt bots. Build one installer for all users. Each person configures the bot locally or imports a JSON plan.

Build once → publish → download repeatedly.
TYPE B

Custom-built installer

Reversal Bot and configurable builds. Visitor chooses settings; the site submits a plan; GitHub Actions builds a customized installer. Premium authorization stays in its existing payment/license flow.

Configure → authorize if required → build → download.

Both types may use GitHub Actions and Cloudflare, but their build and authorization logic remain separate.

6. Release reliability & safety

Artifact retention: GitHub Actions artifacts expire. The current Mini-RSI route searches for the newest matching unexpired artifact. Rebuild before expiration, or eventually move approved installers to GitHub Releases or permanent object storage.

Version control: Record the workflow run, commit SHA, installer version and artifact name for each published bot. Avoid accidentally serving an older build.

Trading safety: A successful installer build does not mean live trading is validated. Test broker connection, observe/paper operation, existing-position handling, shutdown and protective-order behavior separately. Never imply stopping the engine automatically closes positions unless tested and implemented.

Access control: Keep the GitHub token in Cloudflare secrets. The Worker should only download known allowlisted artifacts; preserve existing Premium payment and license checks.
